# Выпуск приложения: Supabase + GitHub Pages

Итог: приложение открывается по постоянному адресу на любом устройстве (телефон, компьютер), данные общие и синхронизируются, а каждая правка после слияния в `main` автоматически выходит в рабочую версию.

```
 правка кода ──► ветка + пул-реквест ──► автотесты ──► слияние в main ──► GitHub Pages (рабочая версия)
                                                                                 │
 телефон / компьютер ◄──── вход по почте и паролю ────► Supabase (база + фото) ◄─┘
```

Адрес рабочей версии: **https://glebvanda.github.io/health-diary/**

Репозиторий: **https://github.com/GlebVanda/health-diary** (публичный, чтобы работал бесплатный GitHub Pages). Нужен аккаунт Supabase (бесплатный).

## 1. Supabase: база данных

1. На [supabase.com](https://supabase.com) нажмите **New project**. Название любое (например, `health-diary`), придумайте пароль базы (сохраните его в менеджере паролей, в приложении он не нужен), регион — ближайший (Frankfurt или Stockholm для России). Тариф Free.
2. Дождитесь создания проекта (1–2 минуты).
3. Слева **SQL Editor → New query**, вставьте всё содержимое файла [`supabase/migrations/0001_init.sql`](../supabase/migrations/0001_init.sql), нажмите **Run**. Должно появиться «Success». Это создаёт таблицу записей, закрытое хранилище для фото и правила доступа: каждый пользователь видит только свои данные.
4. **Authentication → Providers → Email**: включено. Для простоты выключите **Confirm email** (иначе при регистрации придётся подтверждать почту ссылкой из письма, а у бесплатного плана лимит на письма).
5. **Authentication → URL Configuration → Site URL**: `https://glebvanda.github.io/health-diary/` (нужно для писем со сбросом пароля).
6. **Project Settings → API**: скопируйте два значения:
   - **Project URL** вида `https://abcdxyz.supabase.co`;
   - ключ **anon public**. Он публичный по замыслу, его можно хранить в коде: данные защищены паролем входа и правилами доступа. Ключ **service_role** нигде не используйте и никому не передавайте.

## 2. GitHub Pages

Один раз в репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Больше ничего выбирать не нужно: выкладку делает workflow `.github/workflows/pages.yml`, он запускается при каждом слиянии в `main` (и вручную: Actions → Выкладка на Pages → Run workflow).

**Важно про доступ.** Сайт на GitHub Pages открыт всем, у кого есть ссылка. Это нормально, потому что в публикуемых файлах нет личных данных: только код приложения и пустые демо-данные с вымышленными именами. Ваши данные лежат в Supabase за входом по паролю. Но по той же причине **после регистрации вас и других пользователей отключите регистрацию новых аккаунтов**: Supabase → Authentication → Sign In / Providers → выключить **Allow new users to sign up**. Иначе любой, кто найдёт адрес, сможет создать себе аккаунт в вашей базе (чужих данных он не увидит, но займёт ресурсы).

В репозиторий не должны попадать `.env`, ключи, базы данных, бэкапы, `*.xlsx` (они в `.gitignore`).

## 3. Связать приложение с базой

1. В `js/config.js` впишите значения (`hosts` уже указан):

   ```js
   window.HD_CONFIG = {
     supabaseUrl: 'https://abcdxyz.supabase.co',
     supabaseAnonKey: 'ваш anon public ключ',
     hosts: ['glebvanda.github.io'],
   };
   ```

   `hosts` важен: синхронизация включается только на рабочем адресе. На localhost и в других копиях приложение работает локально и **не трогает реальные данные**.
2. Закоммитьте и отправьте через пул-реквест (см. ниже). После слияния workflow выложит новую версию, это занимает около минуты. Статус: вкладка **Actions** репозитория.
3. Откройте рабочий адрес, нажмите **Создать аккаунт**, пройдите настройку. С другого устройства откройте тот же адрес и войдите той же почтой: данные подтянутся.

## 4. Установка на телефон

- **Android (Chrome):** меню ⋮ → «Установить приложение».
- **iPhone (Safari):** «Поделиться» → «На экран „Домой“».

## 5. Как вносить правки удалённо

Правки идут обычным путём Git, поэтому подойдёт любой способ:

- **Через Claude Code** (в десктопе или в вебе claude.ai/code с подключённым репозиторием): опишите правку, Claude создаёт ветку и пул-реквест.
- **Через GitHub в браузере**: откройте файл → карандаш → Commit в новую ветку → Create pull request.

Дальше:

1. В пул-реквесте автоматически запускаются **тесты** (GitHub Actions). У Pages нет превью по каждому пул-реквесту, поэтому посмотреть правку до слияния можно локально (`start.cmd`, http://localhost:8080) или через Claude Code.
2. Если тесты зелёные и правка устраивает — **Merge pull request**. Примерно через минуту рабочая версия обновлена. Приложение на телефоне подхватит её при следующем открытии (service worker обновляется сам).
3. Что-то пошло не так — на GitHub нажмите **Revert** у слитого пул-реквеста и слейте его, либо в **Actions** откройте последний удачный запуск `Выкладка на Pages` и нажмите **Re-run all jobs** (выложится прежняя версия).

Рекомендуется включить защиту ветки `main` (Settings → Branches → Add rule: *Require status checks to pass* → `tests`).

### Выпуск версии

1. Поднять номер в `js/version.js` (он же имя кэша приложения) и описать изменения в `CHANGELOG.md`.
2. Слить в `main`, затем поставить тег: `git tag v1.1.0 && git push --tags` (на GitHub можно оформить Release).

## 6. Что следует знать

- **Данные.** Источник правды — локальная база устройства, облако — её копия. Приложение работает без сети, а изменения уходят при появлении связи. Конфликт одной записи решается так: кто синхронизировался последним, тот и прав. Для одного человека на 2–3 устройствах этого достаточно.
- **Резервные копии.** Раз в неделю-две скачивайте копию (Профиль → Настройки): она включает фото. Бесплатный Supabase не делает ежедневных бэкапов.
- **Засыпание проекта.** Бесплатный проект Supabase приостанавливается после недели без обращений (восстанавливается кнопкой в панели, данные не теряются). Чтобы этого не происходило, добавьте секреты репозитория `SUPABASE_URL` и `SUPABASE_ANON_KEY` (Settings → Secrets and variables → Actions): workflow `keepalive.yml` будет раз в три дня «будить» проект.
- **Лимиты бесплатного плана Supabase** с запасом хватает для личного дневника: 500 МБ базы, 1 ГБ для фото (фото сжимаются до 1600 px).
- **Второй человек.** У каждого человека свой аккаунт и свой дневник. Несколько профилей внутри одного аккаунта тоже возможны (Профиль → Профили), тогда при запуске появляется выбор.
- **Выход из аккаунта** стирает данные на устройстве (в облаке они остаются); «Удалить все данные» с включённой синхронизацией удаляет и в облаке, и на других устройствах.
- **Другой адрес** (свой домен вместо `glebvanda.github.io`): поправьте `hosts` в `js/config.js` и Site URL в Supabase. Данные в браузере хранятся отдельно для каждого адреса, но после входа подтянутся из облака.
