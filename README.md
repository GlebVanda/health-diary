# Дневник здоровья — локальная версия

Мобильный веб-сайт (PWA) для Глеба и Даши: учёт калорий с недельным бюджетом, адаптивный план тренировок под цель и главный экран с прогрессом.

Первая версия работает **полностью локально**: без Git, Supabase, Vercel и без установки Node.js. Это статическое приложение на HTML + JavaScript, данные хранятся в браузере (IndexedDB).

## Запуск

1. Дважды щёлкните `start.cmd` — поднимется локальный сервер на Python и откроется http://localhost:8080.
2. Без Python можно просто открыть `index.html` в браузере: всё работает, кроме установки на главный экран и офлайн-кэша.

При первом запуске приложение сразу ведёт по настройке: анкета подготовки → цели → расписание. PIN при запуске не спрашивается; включить его можно в Профиль → Настройки.

**Установка на телефон:** откройте адрес сервера в браузере телефона (компьютер и телефон в одной сети; для этого запустите сервер с `--bind 0.0.0.0`) → меню браузера → «Добавить на главный экран». Учтите: данные хранятся в том браузере, где их вводили, поэтому для переноса между устройствами есть резервная копия (Профиль → Настройки).

## Выпуск и синхронизация между устройствами

Приложение может работать в двух режимах:

- **Локальный** (по умолчанию, `js/config.js` пустой): данные только в браузере устройства, вход не нужен.
- **С облаком**: вписаны адрес и ключ Supabase, на рабочем адресе включается вход по почте и паролю, и данные синхронизируются между всеми устройствами. Приложение остаётся «локальным в первую очередь», поэтому работает и без сети, а изменения уходят при появлении связи.

Код лежит в репозитории [GlebVanda/health-diary](https://github.com/GlebVanda/health-diary). Пошаговая инструкция (Supabase → GitHub Pages → установка на телефон → как вносить правки удалённо): **[docs/DEPLOY.md](docs/DEPLOY.md)**. Схема базы: [supabase/migrations/0001_init.sql](supabase/migrations/0001_init.sql). Каждая правка идёт через Git: пул-реквест → автотесты → слияние в `main` → автоматическая выкладка на GitHub Pages: https://glebvanda.github.io/health-diary/

Без облака приложение тоже можно поставить на телефон: любой статический хостинг и «Добавить на главный экран», но тогда на каждом устройстве будет отдельный дневник (перенос — резервной копией).

## Что есть

| Блок | Где | Что делает |
|---|---|---|
| Первичная настройка | первый запуск | три обязательных шага, пока они не пройдены, остальные экраны закрыты: 1) анкета подготовки, 2) цели, 3) расписание и оборудование |
| Анкета подготовки | шаг 1, потом Профиль → Оценка подготовки | 4 раздела (о себе, образ жизни, выносливость, сила); выносливость и сила оцениваются отдельно по фактам, ИМТ, ограничение «без бега и прыжков» |
| Серия бега 22 дня | Профиль → Серия бега 22 дня, карточка на главной | календарь 1–22 ноября, утренний чек-ин и светофор, лестница отката А/Б/В/Г, факт пробежки, контрольные точки роста |
| Цели | шаг 2, потом Профиль → Цели | одна основная цель + дополнительные, которые корректируют сценарий основной; проверка безопасности при задании |
| Главная | Главная | прогресс основной цели, тренировка дня, быстрый ввод калорий и веса, неделя, виджет цели, события, рекомендации, раздел «Динамика» со сравнением периодов |
| Питание | Питание | день (ккал + необязательные Б/Ж/У), неделя с переносом перебора, автонорма с историей и ручным переопределением |
| Тренировки | Тренировки | неделя плана, карточка с упражнениями, отметка, автоматические изменения плана с причиной и отменой, перенос на дорожку зимой |
| Профиль | Профиль | личные данные, оценка подготовки, цели, расписание, тело и фото (вес, объёмы, фото, сравнение), события, импорт из Excel, настройки |
| Настройки | Профиль → Настройки | тема, PIN (по умолчанию выключен), ИИ, резервная копия, демо-профили |
| Профили | при запуске | выбор профиля появляется только если в приложении больше одного; добавить профиль можно из Профиль → «Профили» |

## Тесты

Откройте `tests/index.html` через сервер (http://localhost:8080/tests/) — тесты выполняются в браузере: норма, бюджет (цифры из Excel), цели, эталонный план Даши (раздел 6.6), адаптация, рекомендации, агрегаты, валидация правок ИИ, сценарии сервисов и импорт на синтетическом xlsx. Сейчас: 128 из 128; из консоли: `bash scripts/run-tests.sh`.

## Структура

```
index.html, manifest.webmanifest, sw.js   оболочка PWA
supabase/migrations/                       схема облачной базы
scripts/run-tests.sh                       тесты из консоли
CHANGELOG.md, docs/DEPLOY.md               история и инструкция выпуска
css/app.css                                стили, светлая и тёмная тема
js/core/      даты, утилиты, SHA-256
js/domain/    чистые функции расчёта (аналог lib/domain из ТЗ):
              nutrition, budget, goals/* (по файлу на тип цели), plan (generatePlan),
              adapt, recommendations, aggregate, upcoming, exercises
js/ai/        интерфейс AiProvider и проверка правок
js/sync/      клиент Supabase и синхронизация (config.js в js/ — адрес и ключ)
js/data/      хранилище (таблицы как в разделе 3 ТЗ) и начальные данные
js/services/  связка данных и расчётов (аналог серверного слоя)
js/import/    чтение xlsx без библиотек и импорт истории
js/ui/        роутер, графики, экраны
tests/        тесты в браузере
docs/         эталонный план Даши
```

Новый тип цели добавляется одним файлом в `js/domain/goals/` (вызов `HD.goals.register`) и строкой подключения в `index.html`.

## Данные и резервная копия

Всё хранится в IndexedDB этого браузера, включая фото тела (они сжимаются до 1600 px по длинной стороне, это примерно 150–300 КБ на снимок). Резервная копия содержит и фото. Очистка данных сайта в браузере удалит дневник, поэтому регулярно скачивайте копию: Профиль → Настройки → «Скачать резервную копию (JSON)». Восстановление — там же.

Файл Excel читается только в браузере и никуда не отправляется. Не кладите `.xlsx` в папку проекта, если она будет публиковаться (`.gitignore` уже исключает `*.xlsx`).

## Проверка сценариев на другую дату

Добавьте к адресу `?today=2026-11-03` — приложение будет считать этот день сегодняшним (удобно проверить адаптацию и напоминания).

## Переход на Next.js + Supabase (следующие версии)

Расчётная логика в `js/domain` написана чистыми функциями без обращений к хранилищу — её можно перенести в `lib/domain` почти без изменений. Таблицы в `js/data/db.js` повторяют модель данных из раздела 3 ТЗ. Подробности решений — в `DECISIONS.md`.
